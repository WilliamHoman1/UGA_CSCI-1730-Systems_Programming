1. sizeof(s1) is 5 because s1 is a char array initialized from the string literal "zoey", and every string literal ends
with a hidden null terminator. The array holds 4 letters plus the terminator, and sizeof on an array returns its total
size in bytes. The fifth byte, s1[4], stores the null character '\0'.

2. s1 == s2 is false because array names decay to pointers to their first elements when compared, so == comapres memory
addresses, not string contents. s1 and s2 are two seperate arrays stored at different locations. The values being compared
are the addresses &s1[0] and &s2[0], which are different, so the result is false.

3. strcmp compares two strings character by character until it reaches a null terminated, and it returns 0 if they are
identical. s3 points to s1 and s4 points to s2, and at that point in the program both contain "zoey", so strcmp returns 0 and
the condition is true.

4. Array elements are back-to-back in memory with no gaps between them, and a double is 8 bytes on odin. The loop casts the addresses
of d[i + 1] and d[i] to unsigned long and subtracts them, which gives the byte distance between the neighboring elements, which is
always 8. If d starts at address 500: d[0] = 500, d[1] = 508, d[2] = 516, d[3] = 524, d[4] = 532.

5. s4 points to s2, which is a modifiable array. p1 = &s4[0] points to s2[0], so *p1 = 'j' changes the 'z' to 'j'. Then *(&s4[3]) = 's'
is the same as s4[3] = 's', which changes the 'y' to 's'. So s2 and s4 now holds "joes", while s1 is unchanged. s5 printed only "zoey"
because %s prints characters until it reaches the first '\0'. The literal contains an explicit \0 right after "zoey", so printing stops
there, even though " is awesome" is still stored in memory after it.

6. The loop fills q with {5,10,15,20,25}. f(*(q+1), q + 2) passes the value of q[1] (10) as x, and the address of q[2] as y. Setting
x = -2 only changes f's local copy (pass by value), so q[1] stays at 10. Setting *y = -3 writes through the pointer, so q[2] becomes -3.
Therefore, q[1] + q[2] = 10 + (-3) = 7. *(q[1] + q[2]) is not correct syntax: q[1] + q[2] is an int (7), not a pointer, and the
dereference operator * cannot be applied to an int, so it causes a compile error. A correct pointer-notation version is
*(q + 1) + *(q + 2).

7. The addresses change each run because of Address Space Layout Randomization (ASLR). The operating system randomizes where the stack
and other memory segments are placed each time a program is loaded, as a security measure. Since q is a local array on a stack, its
address changes between runs. Output 7 uses %ld, so the addresses are shown in base-10. Output 8 uses %p, so the addresses are shown in
hexidecimal. Both lines show the same addresses: 0x7fffd69821f0 in hex equals 140736793682416 in decimal.
